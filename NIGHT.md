## Как устроен ввод (разобрано, проверено по коду)

scrcpy имеет три режима инъекции: `MIXED` (дефолт), `TEXT`, `RAW`.
Переключение флагом `--prefer-text` → `TEXT`.

**Клиент**, `keyboard_sdk.c`, `sc_key_processor_process_text`:

- в `MIXED` символ приходит, но если `isalpha(c) || c == ' '` — событие
  выбрасывается и вместо него уходит сырой key event. `isalpha` смотрит на
  первый байт, у кириллицы в UTF-8 он `>= 0x80`, поэтому поведение
  непредсказуемое: буква то уходит скан-кодом, то нет;
- в `TEXT` всё идёт через `SC_CONTROL_MSG_TYPE_INJECT_TEXT`.

**Скан-код = US-раскладка.** Когда буква уходит key event'ом, Android
подставляет символ по своей карте физической клавиатуры (US QWERTY).
Латиница и пунктуация совпадают и проходят, кириллица — нет. Отсюда всё
поведение, которое наблюдал пользователь.

**Сервер**, `Controller.injectText`: разбирает строку посимвольно,
`injectChar` → `charMap.getEvents(chars)`. `charMap` — это
`KeyCharacterMap.load(VIRTUAL_KEYBOARD)`, то есть **US QWERTY**. Для `п`
`getEvents` возвращает `null` → лог `Could not inject char u+043f`, символ
теряется. Это подтверждено живым логом с телефона.

**Готовый рабочий путь вставки строки** уже есть в сервере: `setClipboard()`
+ `KEYCODE_PASTE` (так работает Ctrl+V и вставка с Mac). Он не разбирает
строку на клавиши и раскладку не трогает. Кириллица через него на телефоне
проверена: `am broadcast -a clipper.set` + `input keyevent 279` вставляют
`Привет мир` нормально.

## Что уже сделано (коммит 63d0653, состояние НЕ подтверждено живьём)

1. `keyboard_sdk.c`: в `MIXED` больше не выбрасываем буквы и пробел — все
   текстовые события уходят как `INJECT_TEXT`.
2. `Controller.java`: перед посимвольной инъекцией проверяется **вся** строка
   (`canInjectAsKeyEvents`); если хоть один символ не конвертируется — строка
   вставляется целиком через `setClipboard` + `KEYCODE_PASTE`. Проверка идёт
   **до** инъекции, иначе уже набранный префикс задвоится.
3. `MirrorSettings.swift`: `--prefer-text` убран.

Собирается всё, `swiftc -typecheck` проходит. Живьём не проверено.

## С чего начать ночью

1. `git log --oneline -5`, `git status` — убедись, что на `63d0653` и чисто.
2. Собери и поставь: `./build.sh`, затем скопируй `.app` в `/Applications`
   (так же, как делалось: снести старый, скопировать, снять карантин).
3. Открой приложение, подключён телефон по кабелю (`adb devices`).
4. **Добейся надёжного поля ввода.** Прошлый тест на этом и встал. Рабочий
   приём, который сработал: `am start -n com.andharness.ru/.MainActivity`,
   затем `input tap` по полю, затем проверить
   `dumpsys input_method | grep mInputShown` → должно быть `true`.
   Альтернатива, если в приложении поле не ловится: любое поле в другом
   приложении (Заметки, поиск настроек) — для проверки инъекции это
   равноценно.
5. Печатай кириллицей в окно зеркала, снимай `adb exec-out screencap -p`,
   смотри результат глазами через `image_read`. Лог сервера:
   `~/Library/Logs/MyAndroid/scrcpy.log`.
6. Если не работает — смотри лог: если появилось `Could not inject char`
   и **нет** строки про clipboard-фолбэк, значит фолбэк не сработал; если
   строки нет вообще, значит до сервера текст не дошёл и проблема в клиенте.

## Запасной план, если пункт 4/5 не даст результата

`KEYCODE_PASTE` работает не во всех полях. Тогда:

- **Вариант А.** Заменить `KEYCODE_PASTE` на явную вставку через
  `InputConnection.commitText` — но это требует своего IME-компонента,
  тяжело. Не начинать с этого.
- **Вариант Б.** Оставить посимвольную инъекцию, но брать `charMap` не
  `VIRTUAL_KEYBOARD`, а попробовать `KeyCharacterMap.load(deviceId)` для
  физической клавиатуры — пробовал, не помогло, обе карты US. **Не повторять.**
- **Вариант В.** Передавать кириллицу через `setClipboard` + `KEYCODE_PASTE`
  **только для строк, содержащих не-ASCII**, а латиницу оставить как есть.
  По сути это уже сделано в `63d0653` — проверь, что условие срабатывает.

## Провалы, которые НЕ надо повторять

- `SDL_MAC_BACKGROUND_APP=1` — убирает иконку из Dock, но **убивает ввод
  с клавиатуры**. Иконку убираем правильно, через
  `NSApplicationActivationPolicyAccessory` (коммит `6dfc262`), это работает.
- `--legacy-paste` и `--shortcut-mod` — ломают ввод на Android 16 целиком.
- `--prefer-text` сам по себе кириллицу не лечит (сервер упирается в
  US charMap), но и не вредит.
- Патч `Device.injectChar` с юникод-кодом символа — **сломал ввод целиком**
  (ни латиницы, ни цифр, ни пунктуации). Откатили на `b3817ae`. Не возвращать.
- Правка `charMap` на `InputDevice` вместо `VIRTUAL_KEYBOARD` — не помогла,
  обе карты US.
- `--keyboard=uhid` — не помогал.

## Правила работы с телефоном (обязательно)

- Телефон: `3B664A01CVY00000`, OnePlus CPH2795, Android 16.
- `adb` — `/opt/homebrew/bin/adb`, PATH надо выставлять вручную:
  `export PATH="/opt/homebrew/bin:$PATH"`.
- **Не убивать чужие процессы на телефоне**, не менять настройки системы,
  не трогать пользовательские данные. Работать только инъекцией ввода.
- Настройки, которые уже выставлены и трогать нельзя:
  `show_ime_with_hard_keyboard=1`, ADB-клавиатура
  `com.android.adbkeyboard/.AdbIME` установлена. Текущая IME —
  `com.google.android.inputmethod.latin/com.android.inputmethod.latin.LatinIME`.
  Если временно переключал IME — **верни обратно на эту**.
- Скриншоты телефона: `adb -s 3B664A01CVY00000 exec-out screencap -p > /tmp/x.png`,
  дальше `image_read`. Не разглядывать личное без нужды.
- Приложение `com.andharness.ru` — тестовое, поле ввода искать в нём.

## Правила работы с кодом и git

- Править `vendor/scrcpy` можно только точечно и с комментарием, зачем — так
  уже сделано в `mac_activation.*` и `keyboard_sdk.c`.
- Сборка движка: `meson setup` уже настроен в `vendor/scrcpy/builddir`,
  пересборка клиента: `ninja -C vendor/scrcpy/builddir app/scrcpy`.
  Сервер: `cd vendor/scrcpy && ./gradlew --offline :server:assembleRelease`.
  Потом скопировать бинарь и jar в `build/mirror/` — иначе `build.sh`
  возьмёт старое.
- **Сервер пересобирать обязательно** при любых правках `server/`.
- Пуш — по завершении дня или по команде. Коммит-сообщение должно
  говорить, что заработало и откуда откатываться.
- Комментарии в коде — по-русски, как в этом репозитории.
